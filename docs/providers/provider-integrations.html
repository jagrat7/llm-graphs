How LLM Graphs gets its data

Thirteen metric sources and one model catalog. One calls a keyed API, and two read HTML. The other ten download a data file or a JSON response that the leaderboard's own site uses.

1 Anatomy of a source

1
UpstreamLeaderboard sites, APIs and dataset hosts. Nothing is checked into the repo except test fixtures.
2
AdapterOne class per source, registered once in index.ts. Its fetchPayload() is the only code that touches the network.
3
ParseEach row is checked with zod. Bad rows are dropped and logged. A changed version or dataset fails the whole refresh.
4
SourceCacheReturns the stored copy right away and refetches in the background once it goes stale (stale-while-revalidate).
5
AggregatorSplits each row into model id and reasoning effort, then joins the sources into one snapshot.

Sources: providers/index.ts · utils.ts fetchOk / parseRows · cache.ts read · cache.ts fetchAndStore

3 The two scrapers, step by step

AutomationBenchparseAutomationModule ↗
  1. Fetch pagezapier.com/benchmarks as HTML
  2. Find bundleregex for the framerusercontent.com/…/script_main.*.mjs script tag
  3. Find routeregex the import(…) for path /benchmarks. Must stay on the same origin
  4. Fetch moduleread as text and never run
  5. Read tuples[rank,`label`,`score`,`cost`]. The version must be 1.0.6
CursorBenchparseCursorBenchPage ↗
  1. Fetch pagecursor.com/evals, server-rendered
  2. Version checkevery <h1> must read “CursorBench 4.0”
  3. Find tableheaders must be exactly Model · Score · Cost / Tokens / Steps per task
  4. Read cellsstrip tags, decode entities, parse %, $ and counts
  5. Guarda duplicate model name rejects the whole refresh

Neither scraper runs the site's JavaScript. Both fail closed. If the site moves to a new benchmark version or changes the table layout, the adapter throws instead of mixing revisions. The fix is to edit VERSION or a regex.

Sources: automation-bench.ts fetchPayload · cursor-bench.ts fetchPayload

5 Every refresh passes the same gates

The pins are what keep sources apart: ARC-AGI-2 semi-private only, FrontierCode 2.0, CursorBench 4.0, AutomationBench 1.0.6, SWE-bench runs on mini-SWE-agent 2.0.0, LiveCodeBench's 2024-08-01 to 2025-05-01 window, and Harbor dataset ids.

Sources: utils.ts parseRows · metric-provider.ts validatePayload · cache.ts fetchAndStore

6 How often each is refetched

Refreshes are lazy. A request reads the stored copy, and if it is older than refreshWindowMs, a background refetch starts under a lock. Without Upstash env vars, each server instance keeps its own in-memory cache.

Sources: each adapter's refreshWindowMs · cache.ts read · docs/README.md

7 What this means for LLM Graphs

Most likely to break

The scrapers. A Framer rebuild or a new table column stops the refresh. The chart keeps serving the last good copy, which gets older until someone fixes the adapter.

Quietly fragile

The six site JSON files are undocumented. Their versioned paths (v1.1, v2.json, frontier-code-2.0) are pinned in code, so a benchmark update needs a code change.

One secret

Only AA needs a key, and it's the slowest to fetch: up to 100 pages. The cache's 5-minute refresh lock is sized for it.
